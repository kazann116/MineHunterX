# MineHunter X — модель угроз

Документ описывает, от чего MineHunter X помогает защититься, какие допущения сделаны
и как сама программа защищена от злоупотреблений.

## Что обнаруживаем

| Угроза | Признаки (коды правил) | Типичный ложный сигнал и как он гасится |
|---|---|---|
| Скрытый майнер | длительная нагрузка `LOAD_SUSTAINED`, фоновый процесс без окна `LOAD_BACKGROUND`, нагрузка при бездействии пользователя `LOAD_WHILE_IDLE`, имя майнера `MINER_NAME`, параметры майнинга в командной строке `MINER_CMDLINE`, порт пула `POOL_PORT` (только вместе с другими признаками), снижение нагрузки при запуске диспетчера задач `HIDES_FROM_MONITOR` | игры, рендеринг, компиляция, обновления, антивирус: `FULLSCREEN_APP`, `USER_ACTIVE`, `KNOWN_WORKLOAD`, `SIGNED_TRUSTED`, `TYPICAL_FOR_PC`; майнинг по желанию пользователя — исключения |
| Маскировка под системный процесс | системное имя вне системной папки `MASQUERADE`, имя-двойник (`svch0st.exe`, `scvhost.exe`) `NAME_LOOKALIKE` | — |
| Подозрительное расположение | Temp, «Загрузки», `Users\Public`, корзина, корень `ProgramData` `SUSPICIOUS_LOCATION` | программы в папках производителей не считаются подозрительными |
| Нарушение подписи | файл изменён после подписания, недоверенный сертификат `SIGNATURE_INVALID` | отсутствие подписи `UNSIGNED` даёт лишь +10 и не создаёт находку само по себе |
| Закрепление | автозапуск подозрительного файла `AUTOSTART`, запись автозапуска на майнер/подозрительное место | подписанные программы в автозапуске не помечаются |
| Отклонение от нормы | нагрузка выше профиля нормы `ABOVE_BASELINE` | обычная для компьютера нагрузка `TYPICAL_FOR_PC` |
| Причины замедления | системная перегрузка CPU/памяти/диска `SYSTEM_LOAD` | находка категории «необычная нагрузка», не угроза |

Результат — «требует проверки / подозрительно / высокая степень подозрения», а не диагноз.
Каждая находка хранит признаки «за» и «против», недостающие данные, уверенность и версию правил.

## Допущения и границы

- Программа работает с правами пользователя; часть процессов (защищённые, службы других
  сеансов) без прав администратора видна частично — это показывается явно.
- Нет драйвера ядра и внедрения в процессы: руткиты уровня ядра и процессы, скрытые
  от документированных API, не обнаруживаются.
- Нет сигнатурной базы и облачной репутации: известное вредоносное ПО без поведенческих
  признаков может остаться незамеченным. Для проверки файлов используется Microsoft Defender.
- Индикаторы (имена майнеров, параметры, порты пулов) хранятся локально и версионируются;
  злоумышленник может их обойти переименованием — поэтому решение принимается по совокупности.

## Защита самой программы

| Риск | Мера |
|---|---|
| Утечка данных | Анализ локальный, проверка подписи без онлайн-запросов (`WTD_CACHE_ONLY_URL_RETRIEVAL`, `WTD_REVOKE_NONE`). Сама программа обращается в сеть только для проверки обновлений, выключенной по умолчанию: GET `api.github.com/repos/kazann116/MineHunterX/releases/latest` с заголовком `User-Agent: MineHunterX/<версия>`, без сведений о компьютере; ничего не скачивается, открывается только страница выпусков этого репозитория. «Проверить на VirusTotal» (по действию пользователя, с подтверждением один раз за сеанс) открывает в браузере отчёт VirusTotal по SHA-256 файла: хеш считается локально, сам файл не отправляется. Отчёты по умолчанию обезличивают пути и имя пользователя, командные строки не экспортируются. |
| Ошибочное действие пользователя | Остановка процесса, очистка истории — только после подтверждения; критичные системные процессы и сама программа защищены от остановки; повышение прав не выполняется автоматически. |
| Гонка PID | Остановка процесса проверяет время создания (идентичность PID + время создания); при несовпадении действие отменяется. |
| Подмена пути | Пути нормализуются (`\\?\`, `\??\`, `/`, `..`); «Открыть расположение» и проверка Defender принимают только существующие обычные пути без аргументов и кавычек. |
| Подмена разрешённой программы | Исключение может быть привязано к SHA-256: другой файл по тому же пути снова анализируется. |
| Удаление улик и ошибочное исправление | Defender запускается с `-DisableRemediation` (только отчёт). «Исправить» выполняет план только после подтверждения; файлы перемещаются в карантин с манифестом (исходный путь, атрибуты, SHA-256), значения реестра, тип запуска служб и состояние заданий сохраняются; восстановление проверяет SHA-256 и не перезаписывает существующие файлы. Файлы папки Windows, сам MineHunter и критические службы защищены. Навсегда удаляется только файл из карантина и только по отдельному подтверждению. |
| Помехи выключению Windows | При завершении сеанса (WM_QUERYENDSESSION) и закрытии через Restart Manager программа завершается, а не прячется в трей. |
| Сеанс ETW | Именованный сеанс реального времени с минимумом буферов; останавливается при выходе, оставшийся после сбоя сеанс перезапускается. Очередь событий ограничена (потери отражаются в статусе источника). |
| Повреждение истории | WAL, транзакции, `quick_check` при открытии; повреждённая база сохраняется как `*.corrupt-<время>`, создаётся новая. |
| Подмена настроек | Настройки и история — в `%LOCALAPPDATA%\MineHunterX` (права профиля пользователя); запись атомарная; повреждённый файл настроек сохраняется как `.bad-<время>`. |
| Журнал действий | Каждое изменяющее действие (остановка, проверка Defender, очистка истории, исключения, карантин и откат, автозапуск программы, импорт настроек) записывается в журнал. |
| Подлинность программы | Скрипт `tools/sign.ps1` подписывает exe и установщик (SHA-256, метка времени RFC 3161) и проверяет подпись `signtool verify`. |
